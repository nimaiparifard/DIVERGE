2. CORE RESEARCH GAP (your unique angle)
══════════════════════════════════════════════════════════════════════════════

  GNN-only GSL (ProGNN, IDGL, PTDNet, GPS, GRCN, GAug):
    • Revise structure from raw/shallow features (BoW, frozen PLM embeddings).
    • Often joint end-to-end — single adjacency, single feature space.
    • No access to diverse semantic views from multiple fine-tuned LLMs.

  LLM enhancers (TAPE, RoSE, GraphEdit, LLM4GraphTopology, Locle, GAGA):
    • Use LLMs to rewrite text, decompose relations, or edit topology.
    • API cost, hallucination risk, multi-stage pipelines.

  YOUR CONTRIBUTION (DIVERGE + Semantic Structure Enhancer):
    • Native text only — no LLM rewriting at enhancement time.
    • Diverse LLM encodings (multi-view LoRA) provide multiple semantic views.
    • Post-hoc structure refinement per view: cosine pruning OR uncertainty pruning.
    • Three-way diversity: semantic (M LLM views) + structural (M refined graphs)
      + predictive (adaptive ensemble weights).

  STRONGEST ONE-SENTENCE CLAIM:
    "DIVERGE's multi-view LLM encodings provide a free semantic signal for per-view
     graph denoising, yielding three-way diversity that outperforms classical GSL on
     LLM features and LLM rewriting enhancers at lower cost."

──────────────────────────────────────────────────────────────────────────────
A1. LEARNED HYBRID EDGE SCORER (recommended — highest novelty)
──────────────────────────────────────────────────────────────────────────────
Problem: Method II and III are separate heuristics with manual thresholds.
         Reviewers will say "just two known tricks combined."

Idea: Learn a per-edge reliability score on validation data:
      score(e) = α · cos(z_i, z_j) + β · U(e) + optional view-specific bias

Variants to implement and compare:
  • Intersection (conservative): remove e iff cos < T AND U in top-k%
  • Union (aggressive): remove e iff cos < T OR U > T_u
  • Sequential: cosine prune first, then uncertainty on remaining edges
  • Learned α, β via small MLP or logistic regression on validation edges
    (label = whether edge connects same-class nodes, or proxy from GNN val acc)

Why Q1-worthy: Becomes a NEW hybrid enhancer, not two separate post-hoc steps.
Paper name: "Adaptive Hybrid Semantic Structure Enhancement"

──────────────────────────────────────────────────────────────────────────────
A2. MULTI-VIEW STRUCTURE–SEMANTIC CO-ENSEMBLE
──────────────────────────────────────────────────────────────────────────────
Problem: "Structural diversity" claim is intuitive but not proven separate from
         semantic diversity.

Idea: Formalize third diversity axis explicitly:
  • Train GNN on each (view i, refined graph Ḡ_i) pair → M models.
  • Ablation: same M views but ONE shared refined graph vs M per-view graphs.
  • Ensemble weights conditioned on BOTH view index and graph sparsity/homophily.
  • Report: Δacc from structural diversity ALONE (fix embeddings, vary graphs).

Deliverable: Table proving structural diversity adds gain beyond semantic diversity.

──────────────────────────────────────────────────────────────────────────────
A3. ESNR-GUIDED ADAPTIVE THRESHOLD (GPS-inspired)
──────────────────────────────────────────────────────────────────────────────
Reference: GPS — Towards Understanding and Reducing Graph Structural Noise (ICML 2023)
          Dong & Kluger; proposes ESNR metric for structural noise.

Idea: Instead of manual cosine threshold T per dataset/view:
  • Compute ESNR (or simplified homophily-noise ratio) before/after pruning.
  • Auto-select T on validation to maximize ESNR or validation accuracy.
  • Report T selection curve; show method is less hyperparameter-sensitive.

Why Q1-worthy: Connects to top-venue theory; addresses "hyperparameter sensitivity"
               limitation honestly.

──────────────────────────────────────────────────────────────────────────────
A4. HETEROPHILY-AWARE REFINEMENT (ES-GNN-inspired)
──────────────────────────────────────────────────────────────────────────────
Reference: ES-GNN — Edge Splitting beyond homophily (IEEE TPAMI 2024)

Problem: Both enhancers assume deleting low-similarity edges helps.
          On heterophilic graphs (Texas, Wisconsin, Cornell, Actor), this hurts.

Idea: Do NOT delete — SPLIT edges into homophilic vs heterophilic subgraphs;
      route message passing separately (or down-weight heterophilic edges).
  • On homophilic benchmarks (Cora, PubMed): prune (current Method II).
  • On heterophilic benchmarks: split or soft-weight instead of hard delete.
  • Report honest negative result if cosine prune fails on heterophilic data.

Why Q1-worthy: Shows boundary awareness + principled fix; journals reward this.

──────────────────────────────────────────────────────────────────────────────
A5. MINIMAL SUFFICIENT STRUCTURE PER SEMANTIC VIEW (CoGSL-inspired)
──────────────────────────────────────────────────────────────────────────────
Reference: CoGSL — Compact Graph Structure Learning via MI Compression (WWW 2022)

Idea: Each LoRA view i induces a compressed graph Ḡ_i that is "minimally sufficient"
      for view-i GNN performance. Frame pruning as MI compression:
      keep edges that preserve task-relevant information per view.
  • Report % edges removed vs Δacc per view.
  • Show different views retain different edge subsets (structural disagreement).

Theoretical paragraph: connect to "what is a good refined graph" literature.

──────────────────────────────────────────────────────────────────────────────
A6. EDGE ADDITION FOR MISSING HOMOPHILIC LINKS (GAug-inspired)
──────────────────────────────────────────────────────────────────────────────
Reference: GAug — Data Augmentation for GNNs (AAAI 2021)

Problem: Current methods only DELETE edges; cannot recover missing useful links.

Idea: After pruning, add k-nearest neighbor edges in LLM embedding space
      (same-class or high cosine) that are absent from original graph.
  • Prune + add pipeline: delete low-cos, add top-k same-label neighbors.
  • Compare prune-only vs prune+add on WikiCS (dense, noisy).

Why Q1-worthy: Symmetric to LLM4GraphTopology (add/delete) without LLM calls.

7. PRACTICAL GUIDANCE — WHEN TO USE WHICH ENHANCER
══════════════════════════════════════════════════════════════════════════════

  Cosine similarity (Method II):
    → LLM embeddings show clear same-label vs different-label separation
    → Homophily is reasonable for the task
    → Strongest on Cora, WikiCS in current results

  Uncertainty + std (Method III):
    → Large, already homophilic graphs (PubMed)
    → Stable incremental improvement desired
    → Less sensitive to embedding scale than fixed cosine threshold

  Uncertainty + entropy (Method III):
    → Noisy / heterophilic edge patterns (CiteSeer)
    → More hyperparameter tuning acceptable

  Hybrid (proposed Method IV — implement this):
    → Default recommendation for deployment
    → Intersection on homophilic graphs; split/soft-weight on heterophilic
